# 模板使用指南

本仓库即"Qt5 + CMake + Ninja"项目基础模板。Windows 主线为 MSVC，同时
支持 Linux/GCC 构建（见下文"Linux 构建"）。

基于它新建项目时，按下面的必改项清单修改即可，其余构建设施（版本管理、
部署、打包、符号归档、代码统计、单元测试）无需改动。

## 必改项

| # | 位置 | 改成什么 |
|---|------|----------|
| 1 | `CMakeLists.txt` 顶部 `PROJECT_NAME_STR` | 项目名。未改时 configure 会输出 WARNING |
| 2 | `CMakeLists.txt` 顶部 `APP_ORG_NAME` / `APP_APP_NAME` / `APP_URL` | 组织名、应用名与项目主页。前两者决定 `%LOCALAPPDATA%` 数据目录（配置/日志/崩溃）、单实例键、窗口标题，以及安装包的发行者与安装目录层级；改名后旧数据目录不会自动迁移。`APP_URL` 留空则安装包不显示链接 |
| 3 | `CMakeLists.txt` 顶部 `APP_TARGET_PREFIX` | 目标名前缀，预设为 `demo`，拼出 `demo_core` / `demo_libui` / `demo_app`。它决定 exe 文件名、运行脚本名与打包脚本中的目标名，改这一处即可，无需逐个模块改 `TARGET_NAME` |
| 4 | `local.cmake`（仅 Windows） | 本机 Qt 安装路径（x64/x86 两条）。该文件不入库；首次 configure 时若不存在会自动生成并报错提示，改完重跑。Linux 不读取该文件 |
| 5 | `CMakeLists.txt` 顶部 `APP_INSTALLER_ID_X64` / `APP_INSTALLER_ID_X86` | 安装包产品标识（Inno Setup 的 AppId），每个项目必须换新 GUID，否则安装包互相覆盖。配置阶段检测到模板默认值会输出 WARNING；可用 pwsh 执行 `[guid]::NewGuid()` 生成 |
| 6 | `src/app/resources/icons/icon.ico` | 程序图标（嵌入 exe 版本资源） |

以下项已有合理默认，无需修改，需要时再调整：

- 安装包的显示名、发行者、安装目录层级与链接：全部由 `APP_APP_NAME` /
  `APP_ORG_NAME` / `APP_URL` 派生，`cmake/make_install_package.iss.in`
  中不含任何需要手改的字面量。安装目录为 `{autopf}\<组织名>\<应用名>`，
  与 `%LOCALAPPDATA%` 下的数据目录同构
- 安装包图标：`cmake/make_install_package.iss.in` 的 `MyInstallerIcon`
  （默认取程序图标）
- 版本号：由 git 派生 —— 最近的 `v1.2.3` 形式 tag 提供前三段，提交总数提供
  build 号，exe 版本资源中还记录 git 短 hash（工作区有改动时带 `-dirty`）。
  同一提交在任何机器上构建得到同样的版本号。无 git 环境时回落 `0.0.0.0`，
  需要固定版本号时用 `-DAPP_VERSION_OVERRIDE=major.minor.patch.tweak` 指定
- `APP_ARCH_SUFFIX`（x64/x86）与 `APP_MUTEX_NAME`：
  由 `CMAKE_SIZEOF_VOID_P` 与 `APP_APP_NAME` 自动派生

## 目录结构

```text
src/
├── core/    demo_core    无 UI 依赖：配置 / 日志 / 崩溃 / 认证 / 单实例
├── libui/   demo_libui   通用 UI 部件，只依赖 Qt5::Widgets
└── app/     demo_app     界面骨架、资源与样式
```

依赖方向为 `app → libui → Qt`、`app → core`。`libui` 不依赖 `core`，
因此可整包复制到其它工程。

## 可保留的示例

以下内容作为用法示例保留，新项目可在此基础上替换成自己的业务代码：

- `src/app` — 主窗口（菜单栏 + 占位中央控件）、登录、设置、关于、日志窗口
- `src/libui` — `SplashScreen`、`SwitchButton`、`RadialNavigator`
- `src/core/logger` — spdlog 封装（`LOG_INFO` 等宏），建议保留
- `src/core/auth`、`config`、`crashhandler` — 按需保留
- `config/calibration/calibration_sample.ini` — 构建后自动拷贝为
  `bin/calibration/calibration.ini`，是"配置文件随构建输出"的示例
- `tests/core/crashhandler_test.cpp` — 单元测试与子进程崩溃测试的样例

## 按需裁剪

- 顶层 `CMakeLists.txt` 中 3rdparty 的 `add_subdirectory`
  （spdlog、googletest、QCustomPlot、QXlsx）及对应 `target_link_libraries`
- 顶层 `CMakeLists.txt` 中 `find_package(Qt5 ...)` 的组件列表
- `src/app/CMakeLists.txt` 中 calibration 拷贝的 POST_BUILD 示例
- `demoes/` — 本地绘图示例（其子目录未入库，克隆后为空，可整体删除）

## 单元测试

测试放在 `tests/<模块>/`，用 `add_unit_test` 宏注册（宏定义在
`cmake/test_helpers.cmake`，由 `tests/CMakeLists.txt` 引入）：

```cmake
add_unit_test(
    NAME test_core_crashhandler
    SOURCES crashhandler_test.cpp
    LIBS ${APP_TARGET_PREFIX}_core
    QT_MODULES Core Test
    LABELS CORE
    NO_GTEST_MAIN
)
```

| 参数 | 说明 |
|------|------|
| `NAME` | 测试目标名，约定 `test_<模块>_<被测对象>` |
| `SOURCES` | 源文件列表 |
| `LIBS` | 额外链接的库 |
| `INCLUDES` | 额外头文件路径 |
| `QT_MODULES` | 依赖的 Qt 模块，自动加 `Qt5::` 前缀并开启 AUTOMOC |
| `LABELS` | CTest 分组标签，便于 `ctest -L` 过滤 |
| `NO_RUN_SCRIPT` | 不生成运行脚本 |
| `NO_GTEST_MAIN` | 不链接 `gtest_main`（测试自提供 `main`） |

构建后：

```bash
ctest --test-dir build/ninja-debug-x64 --output-on-failure
```

测试可执行文件位于 `<构建目录>/bin/tests/`，与生产产物隔离。

## 扩展指引

**新增一个模块**：在 `src/` 下建目录并写 `CMakeLists.txt`

```cmake
set(TARGET_NAME ${APP_TARGET_PREFIX}_xxx)
add_library(${TARGET_NAME} STATIC ${SRCS})
target_include_directories(${TARGET_NAME} PUBLIC ${CMAKE_CURRENT_SOURCE_DIR})
```

再在 `src/CMakeLists.txt` 中 `add_subdirectory(xxx)`，按需在 `app` 里链接。

**新增一个通用控件**：放进 `src/libui/`，只依赖 `Qt5::Widgets`。若需
样式，用 `setObjectName` 并在 `src/app/resources/styles/default.qss` 中
以 `#objectName` 选择器定义，不在 C++ 里硬编码 `setStyleSheet`。

**新增一个设置页**：在 `src/app/dialogs/settings_dialog.cpp` 中写一个
`createXxxPage()`，再经 `addCategoryPage("分组名", page)` 注册，即自动
出现在左侧分类导航中。控件用 `addSpinBoxRow` / `addComboBoxRow` /
`addCheckBoxRow` 创建，它们会即时写回 `ConfigManager`。

**新增第三方库**：压缩包放入 `3rdparty/` 并在 `cmake/extract_dependencies.cmake`
的 `DEPENDENCY_ARCHIVES` 中登记（首次 configure 时自动解压），再在顶层
`CMakeLists.txt` 中 `add_subdirectory`。

## Linux 构建

前置条件：CMake ≥ 3.26（CMakePresets 为 version 8），以及
`find_package` 所需组件的开发包：

```bash
sudo apt install qtbase5-dev libqt5svg5-dev \
    libqt5serialport5-dev libqt5opengl5-dev
```

> 配置产物目录与 Windows 共用（`build/<presetName>`）。在 WSL 等共享同一
> 源码树的场景下编译，务必指定独立目录，避免覆盖 Windows 侧的 CMakeCache。

```bash
# 配置（独立目录，避免与 Windows 构建产物互相覆盖）
cmake -S . -B build/linux-ninja-debug -G Ninja -DCMAKE_BUILD_TYPE=Debug
# 构建
cmake --build build/linux-ninja-debug
# 测试
ctest --test-dir build/linux-ninja-debug
```

- Linux 不读取 `local.cmake`，Qt 由系统路径解析；必要时用
  `-DCMAKE_PREFIX_PATH` 指定 Qt 安装位置
- 运行脚本由 `configure_run_script` 生成，Windows 出 `.bat`、Linux 出
  `.sh`（自动加可执行权限）
- 部署与打包（windeployqt / Inno Setup）仅 Windows 支持

## 发布

发布一律使用 `relwithdebinfo` 配置，并连同符号一并归档：

```bash
scripts/build_ninja.bat -t relwithdebinfo -p
```

产物位于 `dist/`：安装包与按版本号归档的符号目录。原因、各配置的崩溃
排查能力差异，以及用归档符号解析转储的步骤，见
[构建配置与崩溃排查](构建配置与崩溃排查.md)。
