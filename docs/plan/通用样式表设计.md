# 通用样式表设计

## 问题陈述

模板要"开箱即用"，第一屏的观感就是它的门面。现状是这份表**覆盖严重偏斜**：
`src/app/resources/styles/default.qss` 704 行、135 个规则块，其中滚动条 16 块、
下拉框 15 块、微调框 24 块（QSpinBox + QDoubleSpinBox）、分割器 10 块——四个
复杂控件吃掉 65 块；而**没有裸类型选择器规则的常见控件有 25 个**：QLabel、
QCheckBox、QRadioButton、QTableView、QTableWidget/TreeWidget/ListWidget、
QMenu、QMenuBar、QStatusBar、QToolBar、QToolTip、QDialog、QSplitterHandle、
QProgressBar、QSlider、QFrame、QPlainTextEdit、QDateEdit/QTimeEdit…

（口径说明：`QToolButton`、`QAbstractItemView`、`QHeaderView`、`QWidget` 这几个
类在表里出现过，但都挂在 `#objectName` 后面——`QToolButton#loginButton`、
`QComboBox QAbstractItemView`、`#userManageTable QHeaderView::section`——对别的
项目等于不存在。）

后果：换一个界面（或换个项目），大量控件回落平台默认外观，与已样式化的部分
拼在一起像两个程序。

第二个问题是**业务规则混在里面**：135 个规则块里含 `#objectName` 的有 58 块
（43%），涉及 44 个唯一 objectName，大半是登录 / 改密 / 设置 / 用户管理的业务
控件（`loginButton`、`changePasswordOk`、`settingsCategoryList`、
`userManageTable`…）。这部分对任何别的项目都是死规则。

第三个问题是**文档与实现不符**（两条都在 `CLAUDE.md`）：

- 样式那条要求"优先用 `#objectName` 定位控件"（`CLAUDE.md:64`）。这与"通用"
  直接冲突；更要紧的是 objectName 在本仓是**功能性标识**——funq 的控件路径、
  QtTesting 录制的 XML、`gallery.alias` 都拿它当锚点，样式耦合上去，改一个名字
  要同时动样式、别名表、用例三处。
- 图标那条要求 `AppIconProvider::instance().icon("name")` 且"缺图时新增
  `_light`/`_dark` 两套"（`CLAUDE.md:67-68`）。本仓**没有这个类**，13 个 SVG
  也没有成对的，纯属文档超前于实现。

## 架构回顾

Qt 版本：5.15.2（`local.cmake`）。

| 项 | 现状 | 位置 |
|---|---|---|
| 全局样式加载 | 单点：`ApplyStyleSheet()`（底座层 + 项目层） | `src/style/style.cpp`，调用处 `src/app/main.cpp` |
| guidance 模块的表 | 读自己的表并**追加**到 `app->styleSheet()`，依赖拼接顺序 | `src/guidance/guidance_style.cpp:44-51` |
| 功能区（ribbon） | 主题由 SARibbon 以**窗口级**样式表提供，见下 | `src/app/mainwindow.cpp:87` |
| 图标 | qrc + 直接构造 `QIcon`，无 provider | `src/app/res.qrc` |

**功能区与全局表的关系（原先写错了，此处订正）**：`setRibbonTheme()` 最终是
`w->setStyleSheet(getBuiltInRibbonThemeQss(theme))`——一份打在**主窗口**上的
widget 级样式表（`3rdparty/SARibbon-2.5.7/src/SARibbonBar/SARibbonUtil.cpp:183-186`）。
Qt 的级联规则是"冲突时 widget 自己的表优先"，**不冲突的属性仍由 app 级表提供**。
而主题表里只有 `SARibbon*` 选择器（6 个主题文件的 QScrollBar / QListView /
QMenuBar 计数全为 0），SARibbon 的控件又都是标准件子类——`SARibbonBar :
QMenuBar`、`SARibbonButtonGroupWidget : QToolBar`、`SARibbonToolButton` /
`SARibbonApplicationButton` / `SARibbonGalleryButton` : `QToolButton`、
`SARibbonPanelLabel : QLabel`、`SARibbonPanel` / `SARibbonGallery : QFrame`、
`SARibbonGalleryGroup : QListView`、`SARibbonGalleryViewport : QScrollArea`。

结论：**全局表里的裸类型规则会打进功能区**。现状就能观察到——`default.qss` 的
`QListView{border:none; background-color:#FFF}` 与 16 个 `QScrollBar` 块，正作用
在功能区的画廊与滚动区上，主题里没有任何规则与之冲突。`src/app/mainwindow.cpp:84-86`
那句"default.qss 里的通用控件规则不参与"是错的，实现时一并订正。

现有表的选择器构成（脚本统计，见"参考"）：

```text
行数 704 | 规则块 135 | 含 objectName 的块 58（43%） | 唯一 objectName 44
属性选择器：3 处（[error]、[invalid]）
伪状态：hover pressed checked disabled focus selected alternate horizontal vertical
子控件：17 种（handle groove chunk drop-down indicator item section …）
类型选择器分布：QScrollBar 16、QComboBox 15、QSpinBox 12、QDoubleSpinBox 12、
                QSplitter 10、QListView 4、QPushButton 4、QLineEdit 3、
                QTextEdit 3、QMainWindow 3、QGroupBox 3、其余各 1~2
```

`src/guidance/resources/styles/guidance_default.qss` 是另一套：67 行、13 块，
**全部是 id 选择器**（形如 `QLabel#guidanceHomeTitle`），零裸类型、零伪状态
——它天生就是"项目层"。

表自身还有一个要顺手修掉的毛病：`default.qss:1-3` 是
`* { font-family: "Microsoft YaHei"; }`——正是下面"已知坑"里批评的原型做法。

## 目标与非目标

**目标**：提供一份拿走即用的**底座样式表**（只靠类型 / 伪状态 / 子控件 / 属性
选择器生效）；把现有业务规则收编到项目层；改写 `CLAUDE.md` 两条；产出一份
控件覆盖清单作为工作分解与验收依据。

**非目标**（已定，附理由）：

- **不引入换肤 / ThemeManager**。换肤的价值在"多主题产品"，在这里是负债：参考
  实现在其仓库里有 26 个 `themeChanged` 订阅者（图标缓存、几个 QProxyStyle
  子类、ribbon 上下文页强制重建、占位符色…），初始化与切换还是两份复制粘贴的
  代码。
- **不引入 AppIconProvider**。50 行的东西，但它绑定"主题切换时清图标缓存"这个
  需求——不换肤就不需要。
- **不做暗色主题**。真要做时，分层之后就是重写一遍颜色值，现在不必背两份同步
  成本。
- **不做 QSS 生成脚本**。QSS 没有变量，`@TOKEN@` + 脚本替换会引入一个维护面
  （参考实现里那套生成器已经半废弃：`gen_themes.py` 里 `themes = []`）。
- 不做：QADS 相关样式、CI、i18n（本项目已另行决定不做）。

## 方案

### 分层：底座层 + 项目层

```text
src/style/                       ← 模块 demo_style：底座层住在这里，随模块一起被链走
├── style.h / style.cpp          ← ApplyStyleSheet(app, 项目层路径…)：按序拼接、设字体
├── style_res.qrc
└── resources/styles/base/       ← 底座层：无一条 objectName 规则
    ├── widget.qss               ← 最宽的一条（QMainWindow/QGraphicsView/QStackedWidget），排最前
    ├── button.qss               ← QAbstractButton/QPushButton/QToolButton/QCheckBox/QRadioButton
    ├── input.qss                ← QLineEdit/QTextEdit/QPlainTextEdit/QAbstractSpinBox/QComboBox
    ├── itemview.qss             ← QAbstractItemView/QListView/QTreeView/QTableView/QHeaderView
    ├── scrollbar.qss            ← QScrollBar（原表最大的一组，单列）
    ├── tab.qss                  ← QTabWidget/QTabBar
    ├── container.qss            ← QGroupBox/QScrollArea/QSplitter/QSplitterHandle
    ├── menu.qss                 ← QMenu/QMenuBar/QStatusBar/QToolBar/QToolTip
    ├── progress.qss             ← QProgressBar/QSlider
    └── label.qss                ← QLabel

src/app/resources/styles/default.qss   ← 项目层：本仓业务控件的 objectName 规则
```

底座层做成模块（而不是散在 app 的资源里）是为了"拿走即用"名副其实：别的程序
链上 `demo_style` 再调一次 `ApplyStyleSheet` 就有，不必抄文件、也不会两边漂移
（文件清单只在 `style.cpp` 里有一处）。

**两层顺序**：底座 → 项目层。项目层全是 id 选择器，具体度高于类型选择器，且
拼接在后，双重保险。

**层内顺序**：从宽到窄。QSS 里"所有类型选择器具体度相同、后写优先"，所以
`QWidget{border:…}` 必须排在 `QLineEdit{border:…}` 之前，否则前者会盖掉后者。
这条与文件命名一起写进实现说明（`container.qss` 里的宽规则若与 `input.qss`
冲突，靠文件名排序是保不住的，所以把最宽的 `widget.qss` 单列并置首）。

按控件类分文件的理由来自参考原型（`qt_ui_prototype`）：它是按类试出来的
（每类一个目录、每颜色一份表），维护时也是按类找。反面选项与取舍：

- **把业务规则与通用规则继续混在一份里（现状）**：通用性无从谈起。否决。
- **整表合成一个 700+ 行文件**：按类定位靠搜索，多人同时改必然冲突。否决。
- 底座层内部"按类分文件"还是"单文件"，见决策记录待拍板 1。

### 选择器策略（改写 CLAUDE.md 的依据）

三档，优先级从低到高：

1. **类型 + 伪状态 + 子控件**（底座层只用这三样）。QSS 的类型选择器**带继承
   语义**——Qt 文档冲突解决节的例子就是 `QPushButton` / `QAbstractButton`：
   "Both rules apply to QPushButton instances (since QPushButton inherits
   QAbstractButton)"；滚动条、下拉框、表头这类不写子控件（`::handle`、
   `::drop-down`、`::section`）根本不生效。
2. **动态属性**（角色区分）。`setProperty("role", "primary")` 配
   `[role="primary"]`，C++ 侧改完属性要 `unpolish` + `polish`（本仓已有用例：
   `src/app/log_filter_bar.cpp:142-152`）。现有表里也有 `[error]`、`[invalid]`
   两处在用这个机制。
3. **objectName**（仅项目层，且仅当"这个控件要独立样式、又无法用属性表达"
   时）。理由见问题陈述：它是 funq / QtTesting 的锚点，不该被样式占用。

### 覆盖清单（工作分解，兼验收）

| 类别 | 底座层要覆盖 | 要点 |
|---|---|---|
| 按钮 | QAbstractButton、QPushButton、QToolButton、QCheckBox、QRadioButton、QDialogButtonBox | `::indicator` 决定勾选框外观；`[role]` 区分主/次/危险 |
| 输入 | QLineEdit、QTextEdit、QPlainTextEdit、QAbstractSpinBox（含 QSpinBox/QDoubleSpinBox/QDateEdit/QTimeEdit）、QComboBox | placeholder 走 palette 而非 QSS；QComboBox 的 `::drop-down`/`::down-arrow` |
| 列表与表格 | QAbstractItemView、QListView、QTreeView、QTableView、QHeaderView、QListWidget/QTreeWidget/QTableWidget | `::item` 的 `:selected`/`:alternate`；`::section`；`gridline-color`；QAbstractScrollArea 的 `corner` |
| 滚动条 | QScrollBar（含 `::handle`、`::add-line`/`::sub-line`、`::add-page`/`::sub-page`） | 现状最大的一组（16 块），须完整保留 |
| 选项卡 | QTabWidget、QTabBar、`::tab`、`::pane` | `:selected`/`:hover`；关闭按钮 `QTabBar::close-button` |
| 容器 | QWidget（见坑）、QFrame、QGroupBox、QScrollArea、QSplitter、QSplitterHandle、QStackedWidget | QGroupBox 的 `::title` |
| 菜单与栏 | QMenu、QMenuBar、QStatusBar、QToolBar、QToolTip | `::item:selected`、`::separator`、`::icon` |
| 进度与滑块 | QProgressBar、QSlider | `::chunk`；`::groove`/`::handle` |
| 对话框 | QDialog | 只影响非原生部分 |
| 文本 | QLabel | 最简单，但缺了它整屏都受影响 |
| 主窗口与视图 | QMainWindow（`::separator`）、QGraphicsView | 现状各有 3 块与 1 块，须保留 |

### 已知坑（写进实现，也写进指南）

- **自定义 QWidget 子类设 `background-color` 无效**。三档可选：重写
  `paintEvent` 调 `style()->drawPrimitive(QStyle::PE_Widget, …)`（Qt 文档首选）、
  `setAttribute(Qt::WA_StyledBackground, true)`（本仓已有用例：
  `src/guidance/guidance_homepage.cpp:42,184`）、改用 QFrame。最容易让人以为
  "QSS 没生效"的就是这一条。
- **全局表的裸类型规则会打进功能区**（见架构回顾）。新增 `QMenuBar`、
  `QToolBar`、`QToolButton`、`QFrame`、`QLabel`、`QListView`、`QAbstractButton`、
  `QScrollArea` 这些规则时，**必须同时看功能区有没有被改样**——这是本次新增才会
  引爆的（现状恰好没有这些裸类型规则）。功能区回归点检列为验收项。
- **字体走 `QApplication::setFont`**，不要用 `*` 铺 `font-family`（现状
  `default.qss:1-3` 要一并改掉），也不要在每个类里重复。
- **加载器不要硬编码控件类列表**（参考原型的 `loadAllControlStyleSheets` 写死
  九个类）。用 qrc 里的显式清单，或让 CMake 收集目录。
- **拼接多份表要显式补 `\n`**：`main.cpp` 现在是纯 `+=`，文件末尾没有换行时会
  出现 `}QPushButton{` 粘连（guidance 那边就补了，见
  `guidance_style.cpp:51`）。
- **动态属性改了必须 `unpolish` + `polish`**，否则样式不刷新。
- QFileDialog 等**原生对话框**、以及**非客户区（窗口边框、标题栏）**都不在 QSS
  能管的范围内（本仓主窗口没有设 `FramelessWindowHint`，边框由系统绘制）。
- **`ribbon.qss` 的代价**：主窗口的 widget 级样式表已被 `setRibbonTheme` 占用，
  再叠一份就是在同一层上做覆盖，必须自带整套主题（参考实现的 `ribbon_default.qss`
  433 行 vs SARibbon 的 `theme-office2013.qss` 376 行），并明确与
  `setRibbonTheme` 的先后或拼接关系。仅当"要功能区和其余部分观感完全统一"时才
  值得做。写法（不用 `--`，SARibbon 的类不在命名空间里）：
  `SARibbonBar`、`SARibbonButtonGroupWidget > QToolButton[popupMode="1"]`——
  后者在 SARibbon 自带的 `resource/theme-dark.qss` 里就有。
- guidance 模块的表继续追加到 `app->styleSheet()` 会产生顺序依赖。建议改为
  打在自己那棵子树上（它是可选模块，本来就自成一体），见待拍板 2。

## 决策记录

**已定**（本次讨论）：

1. 只做底座 + 项目层两层，不引入换肤、不引入 IconProvider、不做暗色。
2. 选择器策略改为"类型/伪状态/子控件 → 动态属性 → objectName"三档，objectName
   让给 funq / QtTesting 做功能性标识。
3. `CLAUDE.md` 两处改写：
   - `:64`（样式定位）改成上面那三档；`#objectName` 明确为"仅项目层、仅无法用
     属性表达时"。
   - `:67-68`（图标）删掉 `AppIconProvider` 与 `_light`/`_dark` 的要求，改成本仓
     实际做法（qrc + `QIcon` 直接加载）。
   - `:65`（QPushButton / QToolButton 的取舍）与 `:66`（带命名空间类必须写
     `--`）**保持不动**：后者在本仓不触发（没有命名空间内的 Qt/C++ 类），但
     作为约定留着无害。
4. 借鉴 `etest-demo` 的**机制**（ribbon 表的写法、QADS 场景下的 `--` 用法、
   新增主题手册里的踩坑记录），不搬它的内容（全部 qss 合计 7422 行、
   ThemeManager、IconProvider、QADS 三件套）。
5. 实现时要一并订正 `src/app/mainwindow.cpp:84-86` 那句错误注释。

**待拍板**：无（以下 5 项已于 2026-09-23 拍板）。

**已定（2026-09-23 拍板）**：

1. 底座层内部**按控件类分文件**（十个文件，见"方案"）——按类维护、冲突面小、
   与工作分解一一对应。
2. guidance 那份表**改打在自己的子树上**，不再追加到 `app->styleSheet()`。
3. `ribbon.qss` **本次不做**：先把底座落地，功能区只做回归点检；等"要统一功能区
   观感"时再做（代价见"已知坑"）。
4. 项目层**按判据部分梳理**：满足"同一角色 ≥2 个同类控件"的改走动态属性
   `[role=…]`；形态独一份的控件（如 `settingsCategoryList`）保留 objectName。
5. 颜色**沿用现有色值起步**，只在底座层把混搭的几处（`#333333`/`#858585`/
   `#D7BA7D` 这类）统一成一套带语义注释的取值；"重取色板"留到要换观感时做。

## 验收

不依赖 CI（已定不做）。分两层点检：

- **底座层**：用 `examples/style_demo`（本仓新增的样例程序，链 `demo_style`，
  按控件族分六页）——改完样式表开它逐页点一遍。`libui_gallery`（submodule 里的
  示例）不带本仓的底座层，验不了；往它加控件等于改别人的仓，不动。
- **项目层**：只能在本仓 `demo_app` 里点检（登录、改密、设置、用户管理、日志
  面板、引导）。gallery 里没有这些业务控件。
- **功能区回归**：每个新增的裸类型规则（`QMenuBar`/`QToolBar`/`QToolButton`/
  `QFrame`/`QLabel`/`QListView`/`QAbstractButton`/`QScrollArea`）都要看一眼功能区。

是否需要单独做一个"样式展示页"，留待实现时再定。

## 实现记录（2026-09-23）

**已落地**：

- 底座层十份 QSS 落在新模块 `src/style/`（目标 `demo_style`），由 `style.cpp` 的

- 新增样例程序 `examples/style_demo`：按控件族分成按钮/输入/列表/容器/菜单与栏/
  文本六页，链的就是 `demo_style`，用来眼验底座层；运行脚本由 `configure_run_script`
