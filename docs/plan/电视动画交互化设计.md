# 电视动画交互化设计

状态：**三轮审查（2🔴+10🟡+15🔵）已处置**（2026-10-14），三轮封顶，进入实施。
用户选定"全套信号隐喻"（§3.4）。

## 一、问题与目标

`TvStatic` 对交互无感——`AsciiSceneAnimator` 没覆写
`setInput()`/`onValidationFailed()`，事件到策略层就被丢掉。目标：让电视像
`DefaultCharacterAnimator` 一样对登录窗的 5 个交互事件作出反应，**不动
LoginWindow 与 CharacterPanel**。

## 二、机制（实据）

- `LoginWindow::initSignals()` 把 5 个出口接到 `CharacterPanel` 的 5 个槽
- 面板把状态字段合成 `CharacterAnimator::Input` 整体替换（`setInput()`）；
  `validationFailed` 走 `onValidationFailed()`
- 面板 50ms 的 `tick()` 本来就在跑（可见时），是天然的逐帧钩子
- 失败路径的时序确定：`clear()` → `setFocus()` → `emit validationFailed()`
  （两次 `setInput` 在前，`onValidationFailed` 在后）

## 三、方案

### 3.1 场景侧：绝对覆盖 + 滚动相位

首版设计用"偏置"，一轮审查用源码打穿：`lock` clamp 到 0 时画面 100% 雪花
（`noisy`、`HashT >= pow(0,6)` 恒真），而 `roll`/`tear` 只在测试卡分支消费
——负偏置在雪花相位零像素后果；恒定偏置在锁定平台上又只给常量行位移
（`floor(r+0.956)=r`），"慢跑"不成立。故改成：

```cpp
class TvStatic {
 public:
  struct TvControl {                 // 嵌套在本类里，不落自由类型
    float lock_override = -1.0f;     // <0 用循环自己的 lock；>=0 直接采用
    float roll_extra = 0.0f;         // 叠在 roll 上的行相位
  };
  void SetControl(const TvControl& c);
};
```

- `lock = (override >= 0) ? clamp(override, 0, 1) : loop_lock`——**场景自己夹**，
  不信调用方；`>=0` 闸门同时保证 `pow(lock,6)`/`(1-lock)²` 取值域安全
- `roll` 加 `roll_extra`：折叠由场景**既有的** `fmod(r + roll, kSH+2)`
  承担（模数 17 = 15 可见行 + 2 消隐行），策略不取模也不会出格；策略侧仍
  会把 `roll_extra` 取模 17，防长时间累计后的 float 量化抖动
- **读得出"在滚"的两个条件（三轮审查定稿，缺一不可）**：
  1. 卡片结构稳得住：`noisy` 每帧重抽（`HashT(k,h1,5)`，`k` 帧号自增），
     低 lock 档的卡片是"每帧换一批的随机样本"——要读成"在滚"得
     `0.97·lock ≳ 0.35`
  2. 真有位移：`roll = (1-lock)²·42.5` 在 lock 被覆盖成常量后是**静态偏移**
     （它从来不是速度），**位移动力只来自 `roll_extra`**
  两条件之外还成立的是"在变"：`tear` 的横向抖动逐帧变（rand 每 4 帧换、
  sin 每帧换），所以"卡片卡住但被撕裂打断"也是活的，不是死帧
- 锁定 ≠ 画面全静：`dial`（调谐指针）与 `hum`（交流声带）仍随循环走，
  与"偷看=调谐"的语义正好合

### 3.2 策略侧：电视专属子类

```cpp
class TvStaticAnimator : public AsciiSceneAnimator<TvStatic> {
 public:
  explicit TvStaticAnimator(QRgb background, QObject* parent = nullptr);
  void setInput(const Input& in) override;
  void onValidationFailed() override;
  void tick() override;
  void reset() override;
};
```

- **计时走 `tick()` 倒计数**（800ms=16 帧、2500ms=50 帧，都是 50 的整数倍）：
  面板隐藏时定时器自停、倒计时挂起；连点不叠链，**世代号不需要**；
  `reset()` 清四项：错误倒计时、偷看倒计时、`roll_extra_`（float）、
  上一帧的门控（`prev_gate_`）。递减**必须早于** `ApplyControl()`（否则每档
  多演一帧），写完加 `{}`
- **顺序**：`tick()` = 递减 → 推进 `roll_extra_`（并 `fmod 17`）→
  `ApplyControl()` → `SetControl()` → **再调基类 `tick()`**（基类一进门就
  `Update()`，晚调就稳定滞后一帧）
- **两个时钟的分野（F8）**：`Update()` 吃的是墙钟（`elapsed_`），隐藏期间
  照走；策略的倒计时与相位是帧计数，隐藏期间冻结。所以恢复可见时**雪花
  纹理与循环相位会跳**，而错误/偷看倒计时**原地续跑**（接受这个行为）
- **边沿（F10）**：`setInput` 被鼠标移动高频重入，偷看只在
  `pwd_visible && has_pwd` 的**上升沿**起 800ms。判定必须在**调基类之前**
  做（先 `const Input prev = input();` 再比，或自存 `prev_gate_`）——
  先调基类会让 `input_` 已等于 `in`，上升沿永远不成立、偷看静默失效
- **单一合成点**：`ApplyControl()` 按 `错误 > 偷看 > 打字 > 聚焦` 短路算出
  `TvControl`；错误计时结束按当前 `input_` 重算（`input_` 必然是最新的）
- **语义留白三条（F12 + 三轮 F9）**：① 错误期间点眼睛被短路吞掉（错误
  2500ms > 偷看 800ms，不会补演）；② `has_password` 由 false 变 true 也算
  上升沿，会触发一次偷看；③ **任何档进入时卡片相位都可能跳一下**（`roll_extra_`
  是累计值，档切换时被直接加进画面）——偷看档表现为"吸附到 roll=0"，像
  "调谐器咬住信号"，**保留**，不额外归零
- 覆写 `setInput` 显式调基类（`CharacterAnimator::setInput(in)`），否则
  `input_` 不更新
- `mouse_local` 电视不读
- 子类**不带 `Q_OBJECT`**：理由只有"没有新信号槽 + 只当
  `CharacterAnimator*` 用"（**不是**"模板父类"——具体子类是可以带
  `Q_OBJECT` 的，F18）
- 底色由工厂传入，子类不硬编

### 3.4 映射表（数值经三轮审查逐项算过）

`卡片可见格 = 1 - snow·(1-L⁶)`；**每帧位移 = `roll_extra`**（基础项是静态
偏移，见 §3.1）

| 事件 | 演法 | lock_override | roll_extra | 每帧位移 | 卡片可见格 |
|---|---|---|---|---|---|
| 基线 | 原 10s 循环 | -1（不覆盖） | 0 | 随循环 | 随循环 |
| `typingChanged(true)` | 卡片溶进雪花、被撕裂反复打断（**卡片卡住不滚**，撕裂逐帧变） | 0.45 | 0 | 0 | 44% |
| `passwordFocusChanged(true)` | 轻微失锁 + 画面慢跑 | 0.80 | 0.35 | 7 行/秒（约 2.4 秒一圈） | 83% |
| `passwordVisibilityChanged(true)` | **调谐锁定 800ms**（偷看）：雪花退尽露卡 | 1.0，800ms 后回 | 0 | 0 | 100% |
| `passwordPresenceChanged(has)` | 门控：空密码时偷看不触发 | — | — | — | — |
| `validationFailed()` | 强干扰 2500ms：雪暴 + 碎卡错位 + 滚屏 | **0.40** | **0.8** | 16 行/秒（约 1.1 秒一圈） | 39% |

两处取值的来由（三轮审查）：错误档首版 0.12 → 二轮 0.30 → **终定 0.40**——
0.30 的卡片格占比（29%）低于 §3.1 的"读数线"（`0.97·L ≳ 0.35`），"滚屏"读不
出来；0.40 给 39%，雪仍占 61%，"雪暴"感在。打字档的 `roll_extra` 定 0——
用户选的语义只要求"lock 降 / tear 升"，不要求滚动，硬凑一个相位反而与
"干扰像输入"不符。

## 四、非目标

- Rocket 不接交互（用户只点了电视）
- 不动 Default / Static 两支既有策略，不动 LoginWindow 与面板
- 不改电视的 10 秒循环本身

## 五、验收

1. 两条界面路线编译通过；ctest 与改动前一致
2. **没有可读的状态载体**（二轮 F14）：funq 只能定位 QWidget，策略是普通
   QObject 且面板不暴露动画状态——**全部用抓图**：`client.widget(path=...)`
   取到 oid 再 `send_command("grab", oid=...)`。每条约抓 2–3 帧，**帧间距
   ≥500ms**（50ms 一帧、0.35 行/帧下，相邻两帧约 2/3 概率看不出行位变化，
   三轮 F4b）
3. **判据用"可辨认形态"，不用"与基线一致/不同"**（三轮 F4a）：基线是墙钟
   驱动的 10 秒活循环，任意两次采样相位必不同。形态对照表：
   满屏测试卡（偷看）/ 约四成碎卡 + 横向撕裂（打字）/ 约八成卡慢跑（聚焦）/
   约四成卡 + 六成雪 + 滚屏（错误）
4. **归一化穿梭**（三轮 F3）：`activate_focus()` 依次给 用户名 → 密码 →
   用户名。三段穿梭穷举覆盖四种来源——`editingFinished` 只在"产生 typing 的
   那个框此刻有焦点"时才会随焦点移开而发，先给焦点再移开才补得出这次
   `FocusOut`；顺带把"聚焦子例时密码框无焦点"变成确定前提
5. 逐条驱动作法与判据：
   - 聚焦：穿梭后调密码框 `activate_focus()` → 抓帧应见卡片慢跑（帧间距
     ≥500ms 才看得出行位移动）
   - 偷看：**先抓一帧"点击前"**——循环自己的锁定平台上（u∈[3.4,6.6]）画面
     本就接近满卡，直接比会假阴性；若点击前已是满卡就等 2–3 秒重来。确认
     起点是雪相位后：`set_property("text", …)` 让密码非空（门控）→ 点眼睛
     → 卡片出现；**+1500ms** 回雪（800ms 的余量太紧，三轮核实实到约 750ms）
   - 门控：**眼睛先置回 off**（上一条结束时是 on，直接点会变成关动作、
     测不到边沿）→ 清空密码 → 点眼睛 → 无变化
   - 打字：`client.widget(path=…PASSWORD).keyclick("a")`——**必须带 oid**
     （客户端级 `keyclick` 打到 activeWindow，QDialog 不转发，静默无效）；
     `set_property` 只发 `textChanged`，驱动不了打字
   - 错误：**先清空两个输入框**（配置会预填用户名/密码，不 clearing 走的是
     真实鉴权失败分支，它会 `setFocus()` 到密码框、错误结束后落进聚焦档）→
     提交 → 强干扰约 2500ms → 归一化后回雪
6. 连点眼睛 3 次（先归一化）：+300ms 仍见卡、+1500ms 回雪

## 六、决策记录（2026-10-14）

1. **演法用"全套信号隐喻"**（用户选定，§3.4）
2. **场景控制量用绝对覆盖 + 滚动相位，不用偏置**（一轮 🔴）
3. **计时走 `tick()` 倒计数**，不用 `singleShot` + 世代号（一轮 🟡）
4. **新建 `TvStaticAnimator` 子类**；通用壳只把 `scene_` 放宽到 protected
5. **偷看按上升沿触发，且判定早于调基类**（一轮 🟡 + 二轮 F10）
6. **错误档 lock 定 0.40**（二轮 0.12→0.30，三轮再提到 0.40：0.30 低于
   §3.1 的读数线，"滚屏"读不出来）
7. **打字档不滚**（三轮 🔴：基础项是静态偏移不是速度；用户语义也没要求滚）
8. **验收全部走抓图 + 归一化穿梭**（二轮 F14 + 三轮 F3/F4：没有可读状态
   载体、持续态会污染期望值、基线不可当判据）
