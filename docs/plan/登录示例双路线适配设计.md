# 登录示例双路线适配设计

状态：**已决策，三轮审查收敛（无阻塞项）**（2026-10-13）。对象是
`examples/new_login_dialog`——网页版 `temp/11/Login.html` 的 Qt 移植：左侧会
眨眼、会看鼠标、会捂眼、会偷看的自绘角色面板 + 右侧登录表单。三轮审查的
12 + 9 + 11 条都已逐项落进本文（见 §八）。

## 一、问题与目标

### 现状

- **17 处 `setStyleSheet` 把 QSS 串写在 C++ 里**（`fieldStyle()` / `pwdFieldStyle()`
  两个 helper 连 `:focus` 都拼在代码里）——违反本仓硬规则
- **全文件 0 处 `objectName`**：funq 路径与 QtTesting 录制的锚点缺失
- main 只有 4 行：**没 include、没调 `ApplyStyleSheet`**，而 CMakeLists 已经按
  qss 路线链了底座并注入了 `APP_UI_QSS`（`CMakeLists.txt:15-21`）——宏定义了没人
  用，底座样式表实际从未加载；且那个 `if` 没有配对的 `else()`，fluent 路线下连
  应用样式都没人设
- 那份 CMake 注释是从 fft_demo 抄的（"它们没有自己的项目层"），对本示例不成立
- CMakeLists 还链了 `${APP_TARGET_PREFIX}_tour`，cpp 里 0 处用到——白链
- 头保护宏抄了目录：`FILE_APP_DIALOGS_LOGIN_WINDOW_H_`
- 界面函数名是 `buildUi()` / `wireSignals()`，规则 3 要求 `initUi()` / `initSignals()`
- **fluent 路线完全没有适配**：示例是独立 exe（没有 demo_app 那个 `Application`
  类），没人给它设 `FluentUI3Style`，也没有任何分支

### 目标

1. 守本仓规矩：**标准控件的外观全进 QSS 文件**、控件补 objectName、零内联样式表。
   插画与自绘按钮（`CharacterPanel` / `HoverButton`）维持 QPainter——它们没有对应
   的 QSS 载体；这与 plan总结 B6（`TourCard` 自绘**抢走了标准控件**的外观）不是
   一回事，那里是自绘去盖 QSS，这里是自己画自己
2. **两条路线都完整**：`APP_UI_ROUTE=qss` 与 `fluent` 下都能编、能跑、不缺胳膊
3. 保住"看思路"的部分——自绘角色面板与 HoverButton 的动效是设计本体，不动
4. 补齐网页原版的彩蛋：**偷看**（已实现，见 §五）

### 非目标

- 不追求两条路线像素级一致（D5 已定：fluent 路线接受 Fluent 默认观感，
  见 plan总结 的「界面双路线与 FFT 选型」）
- 不给这个示例写 funq 用例；补 objectName 只是留锚点
- 不引入 Frameless：登录窗是固定尺寸的顶层窗口，fluent 路线只换样式（主程序
  登录框在 fluent 路也是退回普通对话框 + 原生标题栏，同一取舍）

## 二、分界：哪些交给样式表，哪些本来就是自绘

| 部分 | 谁负责 | 理由 |
|---|---|---|
| `CharacterPanel`（背景/logo/footer/角色） | QPainter 自绘，**两条路线相同** | 插画本体，不是"控件皮肤" |
| `HoverButton`（hover 动效） | QPainter 自绘，**两条路线相同** | 动效即设计，Fluent 无对应能力 |
| 右侧表单：输入框、眼睛按钮、复选框、标题/副标题/字段标签、右栏底色 | **路线各自表达** | 它们就是标准控件的外观 |

一句话：**自绘的是"画"，控件的是"皮肤"；皮肤随路线走，画不动。**

### 版式与皮肤的分界（本次定案）

**字号 / 字重 / 边距 / 控件尺寸算版式**，用 `QFont` 与布局代码表达，两条路线共用
同一份；**颜色 / 边框 / 背景算皮肤**，qss 路线进项目层 QSS，fluent 路线交给
Fluent 自己画。

**例外一：输入框的 `padding` 不算版式**——底座层已经用 QSS 定了
（`src/style/resources/styles/base/input.qss:9-21` 的 `padding: 4px 12px`），而
`QLineEdit::setTextMargins` 是在 QSS 之上**叠加**、不是替换。所以输入框的 padding
与边框一起放项目层，代码里不设。

**例外二：错误标签的字号不另设**——底座层 `QLabel[role="error"]`
（`base/label.qss`）已定 12px，qss 路线就用它（原内联的 12.5px 丢弃，0.5px 无
意义），fluent 路线随 Fluent 默认字号——与"错误态颜色随路线"同一条定案。

**例外三：装饰性内边距跟着皮肤走**——横幅/面板这种"整块画出来"的内边距
（`#loginError` 的 padding）算皮肤，进项目层；控件之间的间距才是版式，用布局
表达。一句话判据：**底座已经声明过的属性就得放回 QSS**——`setTextMargins` 是
叠加不是替换，一半在代码一半在 QSS 只会打架。

## 三、qss 路线

- 示例自带**项目层** qss：`examples/new_login_dialog/login_window.qss`，只写挂在
  该示例 objectName 上、且属于"皮肤"的规则（本仓项目层规矩）
- 进示例自己的 qrc（`login_window.qrc`）：qss 挂在 `"/new_login_dialog"` 前缀下；
  **另要把 `:/resources/icons/svg/check.svg` 按底座层期望的路径登记进来**——底座
  `base/button.qss:125` 的 `image: url(.../check.svg)` 指向它，而该 svg 只登记在
  `src/app/res.qrc`，示例是独立 exe 拿不到，不登记勾选态就没有勾。用
  `<file alias=...>` 指回 `src/app/resources/icons/svg/` 那份，不复制文件
- **`.qrc` 必须列进 `ALL_SRCS`**；exe 自己 qrc 由 AUTORCC 生成的静态初始化器
  自动注册，不需要 `Q_INIT_RESOURCE`（那是静态库才要的，见
  `src/style/style.cpp:42-47`）
- main 里 `ApplyStyleSheet(app, {QStringLiteral(":/new_login_dialog/login_window.qss")})`
- 底座层照旧由 `${APP_TARGET_PREFIX}_style` 提供（输入框的基础外观来自它；复选框
  的底色/边框也在底座，但勾图资源要示例自己登记，见上）
- 字体：`Microsoft YaHei` 由 `ApplyStyleSheet` 顺手设（`src/style/style.cpp:76-81`），
  qss 路线不用另设

17 处内联样式的去向（逐条）：

| 现在 | 去处 |

## 四、fluent 路线

- **不加载任何 QSS**（铁律：QSS 一生效，命中控件就走 `QStyleSheetStyle`，Fluent
  的绘制被整个绕过；出处 `src/app/application.cpp:31-33`、
  plan总结「界面双路线与 FFT 选型」硬约束 1）
- **宏口径沿用三个既有示例的 `APP_UI_QSS`**（全仓 `APP_UI_FLUENT` 只在
  `src/app/CMakeLists.txt:145` 注入过，示例里从没用过）：

```cpp
// main.cpp —— 两条路线是全集，所以 #else 就是 fluent
#ifdef APP_UI_QSS
#include <style.h>           // 只在 qss 路线编得到
#else
#include <fluentui3style.h>  // 只在 fluent 路线编得到（全局命名空间）
#endif

int main(int argc, char* argv[]) {
  QApplication app(argc, argv);
#ifdef APP_UI_QSS
  ApplyStyleSheet(app, {QStringLiteral(":/new_login_dialog/login_window.qss")});
#else
  app.setStyle(new FluentUI3Style);
  // FluentUI3Style 不管应用字体，这里补上（qss 路由 ApplyStyleSheet 设）；
  // 与 src/app/application.cpp:34-41 同序：先样式后字体
  QFont app_font = app.font();
  app_font.setFamily(QStringLiteral("Microsoft YaHei"));
  app.setFont(app_font);
#endif
  ...
}
```

- CMake 的 if/else 与 `examples/fft_demo/CMakeLists.txt:25-28` 同形：
  qss 路链 `${APP_TARGET_PREFIX}_style` + 注入 `APP_UI_QSS`；`else()` 链
  `FluentUI3Style`。**这是第一个显式设 `FluentUI3Style` 的示例**（其余示例在
  fluent 构建里是系统默认样式），有意为之——本示例的目标就是"两条路线都完整"
- 表单控件外观交给 Fluent：输入框圆角、聚焦高亮、复选框都由它画

### 两条路线的差异表（已定案）

| 项 | qss 路线 | fluent 路线 | 定案 |
|---|---|---|---|
| 输入框 | 下划线式（设计稿） | Fluent 圆角框 | 接受差异（D5：不翻属性） |
| 聚焦色 | 紫 `#5b21b6` | Fluent accent | 接受差异 |
| 右栏底色 | 白（项目层） | 系统窗口色 | 接受差异 |
| 眼睛按钮 | 无边框字形（项目层） | Fluent 标准工具按钮（会画 hover 底与内边距） | 接受差异 |
| **错误态** | 红字横幅（项目层）+ 角色抖动 | 默认文本色 + 角色抖动 | **机制一致、颜色随路线**——与主程序登录框同款（`src/app/dialogs/login_dialog.cpp:137-140` 只用 `role="error"` 文本，fluent 路同样没有 QSS）。不做"输入框变红"：qss 能画下划线红、fluent 画不出，做了必然不一致 |
| 字体族 | `Microsoft YaHei`（`ApplyStyleSheet` 设） | 同左（示例 main 的 `#else` 分支设） | 完全一致 |
| 字号/字重/边距/控件尺寸 | 代码（版式） | 代码（版式） | 完全一致 |
| HoverButton / 角色面板 | 自绘 | 自绘 | 完全一致 |

## 五、网页原版的彩蛋：偷看（已实现）

原版 `isPurplePeeking`：密码**显示**出来之后，紫色角色每 2–5 秒偷瞄一眼（瞳孔从
`(-4,-4)` 甩到 `(+4,5)`，800ms），**只有它一个**这么干——一个角色的戏。

移植（本次已写进工作区）：

- `CharacterPanel::schedulePeek()`：递归 `QTimer::singleShot`（随机 2000–5000ms，
  偷看 800ms）；条件 `has_pwd_ && pwd_visible_` 不成立就不再排下一次
- **链条唯一**：`setPasswordVisible(true)` 进 `schedulePeek()`，世代号自增在那里
  发生（且只在 `has_pwd_ && pwd_visible_` 成立时）；在飞的旧链（连同它的 800ms
  收尾）拿到过期世代号后直接返回。没有这一层，反复点眼睛会叠出多条链，偷看频率
  越点越高（二轮审查抓出的实现缺陷，与 `error_gen_` 同款手法）
- `setPasswordVisible(false)` / `setHasPassword(false)`：`peeking_ = false` 之外
  再 `++peek_gen_`，把在飞的链一并作废
- `updateTargets()` 的 `showing_pwd` 分支：`i == 0 && peeking_` 时瞳孔 `(4,5)`，
  否则 `(-4,-4)`；**眼睛位置不变**（原版就只动瞳孔）
- 定时器都带 context 对象（`this`），面板销毁后不会回调

`qApp->installEventFilter(this)`（喂鼠标位置用）与样式路线无关，两条路线等价，
不动。

## 七、验收

1. 两条路线各编一次。qss 路线照旧 `scripts\build_ninja.bat -t relwithdebinfo -a x86`；
   fluent 路线要独立构建目录，且**必须在 VS2019 x86 环境里跑**（preset 只固定
   Ninja 与编译选项，架构靠 MSVC 环境决定，普通 cmd 直接跑会
   `No CMAKE_CXX_COMPILER could be found`）——先
   `call "D:\Program Files (x86)\Microsoft Visual Studio\2019\Community\VC\Auxiliary\Build\vcvars32.bat"`，
   再 `cmake -S . --preset ninja-relwithdebinfo-x86 -B build/ninja-relwithdebinfo-x86-fluent -DAPP_UI_ROUTE=fluent`，
   再 `cmake --build build/ninja-relwithdebinfo-x86-fluent`（第一句只配置不构建）
2. 两条路线各启动一次（`bin\run_new_login_dialog.bat`），肉眼确认：版式与字号
   一致、表单完整、角色面板动效在、偷看在、错误态"文字 + 抖动"两路都在、记住密码
   勾上后是紫底**带勾**（qss 路线）
3. qss 路线：`grep -c setStyleSheet examples/new_login_dialog/*.cpp` 为 0；
   再看 qss 是否真加载——示例是 WIN32 子系统没有控制台（`qWarning` 看不见，
   `src/style/style.cpp:30-38` 只在读失败时静默告警），手段二选一：DebugView 抓
   一次 `OutputDebugString`，或临时在 main 里 `qDebug() << app.styleSheet().size()`
   看一眼再删。最省事的是看第 2 步的截图：下划线式输入框出来了就说明底座 + 项目层
   都命中了
4. fluent 路线：不加载任何 QSS，同样按第 2 步的观感判定（Fluent 圆角框、Fluent
   焦点高亮）；`qApp->styleSheet()` 不是控件属性，funq 读不到，别指望拿它验
5. 右栏白底若没出来，`right_` 是裸 `QWidget`（靠 Qt 自动加 `WA_StyledBackground`
   才画 `background-color`，样式表里带背景通常会自动加）——真不生效就给它
   `setAttribute(Qt::WA_StyledBackground)` 或换 `QFrame`，以实际效果为准
6. ctest 与改动前一致（数量以改动前 `ctest -N` 实测为准，别写死数字）
7. objectName 补完后可寻址：手工造一份 `funq.conf` 放 `temp/`——段名用
   `funq_target`（`tests/funq_demo/probe_widgets.py:57` 写死了这个段名），
   `executable` 指向本示例 exe，复用 funq_demo 那份探针，`aliases` 可省；别用
   `funq_app` 那份（它的探针会先 `ensure_logged_in`，示例没有那套流程）

## 八、决策记录（2026-10-13）

1. **字号/边距算版式**（输入框 padding 例外，见 §二）：用 `QFont` 与布局代码，
   两条路线共用一份；只有颜色/边框/背景算皮肤
2. **错误态**：机制两条路线一致（错误文字 + 角色抖动，不做输入框变红）；
   文字颜色随路线（qss 红字横幅 / fluent 默认色），与主程序登录框同款
3. **示例在 fluent 构建里也编**：与其它示例一致都能编；不进安装包（`.iss` 只收
   主程序），跑法用 `bin\run_new_login_dialog.bat`
4. **改动落在 `new_login_dialog` worktree 分支上**
5. **宏口径用 `APP_UI_QSS`**（示例既有做法），`#else` 即 fluent；不新引入
   `APP_UI_FLUENT`（一轮审查 🔴1 的选项 a）
6. **peek 单链**（二轮审查 🟡）：反复触发不叠链，用世代号作废旧链——已改在
   `login_window.cpp`，见 §五
7. **错误标签字号随路线**（二轮审查 🔵）：qss 用底座的 12px、fluent 随 Fluent
   默认，内联的 12.5px 丢弃——见 §二 例外二
8. **fluent 路线在 `#else` 分支里自己设应用字体**（3 行，仿
   `style.cpp:76-81`）；qss 路线由 `ApplyStyleSheet` 设。不抽 helper——抽了在
   qss 路线就是死函数，`/W4` 会报（二轮审查 🔴2 + 实现时实测）
9. **复选框四态写全、勾图资源示例自理**（三轮审查 🟡2/🟡3）：`#id` 具体度高过
   底座的类型选择器，只写一条无伪态的规则会把勾选态底色一起盖掉；勾图
